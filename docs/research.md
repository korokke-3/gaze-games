# Webカメラ視線推定の技術調査

このアプリの視線推定エンジン（`--engine webeyetrack`、既定）を **WebEyeTrack**（Davalos ら、2025）と同じ構成にした理由と、その背景技術をまとめる。

出典は末尾に挙げる。【論文】は WebEyeTrack 論文（arXiv:2508.19544）の本文を読んで確認した内容。【コード】は公開実装（MIT License）を読んで確認した内容。【一般】は分野の通説で、今回は個別の文献に当たっていないもの。

---

## 1. 手法の系統

| 系統 | 入力 | 出力までの流れ | 長所 | 短所 |
|---|---|---|---|---|
| **モデルベース（幾何）** | 瞳孔・虹彩・角膜反射・目の輪郭 | 眼球モデル + 頭部姿勢 → 3D視線ベクトル → 画面の平面と交差 | 原理的に頭の動きに強い。学習データが不要 | カメラ較正、画面の位置関係、高解像度の目の画像が必要。赤外線照明が前提の手法が多い |
| **特徴量回帰** | 虹彩位置などの少数の特徴量（例: WebGazer の目の画素、MediaPipe の虹彩） | 個人ごとの回帰（リッジ回帰、SVR） | 軽い。少数の較正点で動く | 頭の動きに弱い。WebGazer では20分で誤差が約5cm→約10cmに悪化したと報告されている【論文】 |
| **外観ベース（深層学習）** | 顔や目の画像 | CNN/ViT → 視線方向（3D）または画面上の点（2D） | 頭の動きや照明の変化に強い。大規模データで汎化する | 人をまたぐ汎化には限界がある（未知の人で 4〜7°程度）。個人適応が効く |

現在の主流は **外観ベースの深層モデルに、頭部姿勢と少数点の個人適応を組み合わせる** 方式である。WebEyeTrack はこれを、ブラウザや CPU で動く軽さで実現した例になる。

## 2. 主なデータセット

| データセット | 規模・条件 | 用途 |
|---|---|---|
| MPIIGaze / **MPIIFaceGaze** | 15人のノートPCの日常利用（Webカメラ）、各人約3000フレーム | Webカメラ画面視線の標準的な評価。WebEyeTrack が公開している重みはこれで学習されている【論文・コード】 |
| **GazeCapture** | iPhone/iPad で 1450人以上、250万フレーム以上をクラウドソーシングで収集【論文】 | モバイルの2D視線点。iTracker 論文で導入 |
| EyeDiap | 16人、HDカメラ、実験室【論文】 | 頭の動きを含む評価 |
| ETH-XGaze | 110人、110万枚、6000×4000の高解像度、極端な頭部姿勢と16種の照明（ECCV 2020） | 頭の向きが大きく変わる条件での学習 |
| Gaze360 | 屋外の360°カメラ、視線の範囲が広い | 顔全体の画像からの3D視線 |

## 3. 前処理: データ正規化

外観ベースの手法では、頭部の回転（とくに視線軸まわりの回転）とカメラまでの距離を打ち消すように、**仮想カメラで顔や目を正面から撮り直した画像** に変換するのが標準である（Sugano 2014、Zhang 2018 "Revisiting data normalization"）。ETH-XGaze では、焦点距離960mm・距離300mm の仮想カメラに正規化している。

WebEyeTrack はブラウザで高速に動かすため、PnP（`solvePnP`）を使う正規化をやめた。代わりに **顔の4つのランドマークからホモグラフィを求めて顔を正面化し、目の帯を 128×512 に切り出す** という簡略版を使っている【論文 4.1・コード `obtain_eyepatch`】。

## 4. モデル構造（WebEyeTrack / BlazeGaze）【論文 3〜4章・コード】

1. **MediaPipe Face Landmarker**: 478点のランドマークと、顔の変換行列（回転と並進）を出す。
2. **目の画像**: 顔の4点（103, 150, 379, 332）を外側へ広げた四角形を 512×512 に射影し、眉間（151）から鼻（195）までの帯を 128×512 に縮小する。
3. **頭部ベクトル**: 顔の変換行列をオイラー角にし、向きの単位ベクトルに直したもの（3次元）。
4. **実寸での顔の3D位置 [cm]**:
   - 虹彩の直径を1.2cmと仮定し、虹彩と顔幅の比から顔幅[cm]を推定する。
   - 正規化した顔メッシュを実寸に拡大して回転させる。
   - 鼻の位置を合わせたあと、各点の半径方向のずれから奥行き Z を最大10回反復して修正する（Procrustes 解析の一種）。
   - 両目の目頭と目尻の中点を「視線の原点」とする。
5. **BlazeGaze**:
   - エンコーダ: BlazeFace 由来の BlazeBlock を使う CNN。128×512×3 の画像から 512次元の埋め込みを出す。
   - デコーダ: 埋め込みから目の画像を再構成する。学習時にだけ使う。
   - 視線 MLP: [埋め込み512 + 頭部3 + 顔位置3] を入力に、16 → 16 → 2 の3層で、画面上の正規化座標 [-0.5, 0.5]²（画面中心が0）を出す。
   - 規模はパラメータ0.16M、0.15 GFLOPs、モデルは約670KB【論文 表1】。
6. **後処理**: EAR（目の縦横比）< 0.2 なら閉眼とみなして推定しない。そのあとアフィン補正をかけ、カルマンフィルタで平滑化する。

## 5. 学習方法

### 5.1 一般的な学習方法【一般】
- **教師あり回帰**: 視線角（pitch, yaw）や画面上の点に対して、L1・L2 や角度誤差の損失を使う。
- **分類 + 回帰**: L2CS-Net は角度をビンに分けた分類損失と回帰損失を組み合わせる。
- **自己教師あり・表現学習**: 視線を区別できる埋め込みを先に学習する（例: FAZE の視線を意識したオートエンコーダ）。
- **ドメイン適応・汎化**: データセット間（実験室とスマホ、など）の差を埋める。
- **個人適応**: 少数の較正点で次のいずれかを行う。
  - 全体を微調整する
  - 最終層だけ更新する
  - バイアスやアフィン補正だけを推定する
  - メタ学習（MAML）で「数点で適応しやすい初期値」を学習しておく（FAZE 2019、WebEyeTrack 2025）
- **暗黙の較正**: クリックなど、ユーザーの操作の瞬間を正解ラベルとして使う（Sugano 2015、PACE、WebGazer）。

### 5.2 WebEyeTrack の2段階学習【論文 3.2・4.3】
**第1段階: 視線を意識した表現学習（エンコーダ・デコーダ・MLP を同時に学習）**

損失は次の3つの重み付き和 L = β_r·L_r + β_g·L_g + β_c·L_c である。
- L_r: 画像の再構成誤差（MSE）
- L_g: 視線点の重み付き L2 誤差。画面を30×30に分けたときの頻度の逆数で、各サンプルに重みを付ける（ラベルの偏りの補正）
- L_c: 埋め込みの一貫性損失。2サンプル間の埋め込みの距離を、視線点の距離（正規化したもの）に合わせる対照学習風の損失

設定は 20エポック、バッチ8、Adam（学習率1e-3を0.95で指数減衰）。最良のモデルを保存し、デコーダは捨ててエンコーダを固定する。

**第2段階: メタ学習（一次近似の MAML）**
- 「人」を1タスクとし、支持集合 k=9、評価集合 l=100 とする。
- 内側ループは SGD（α=1e-5）を5回、外側ループは Adam（η=1e-3）で1000ステップ。
- 学習するのは視線 MLP だけで、エンコーダは固定する。

**実行時の個人適応（公開実装のデモ）【コード】**
- 4点（正規化座標で ±0.4）を、各2秒表示する。
- 点ごとに集めたフレームのうち、予測の平均に最も近い1枚を選ぶ。
- 過去の較正データと合わせてアフィン補正を最小二乗で求める。
- そのうえで MLP を Adam（lr=1e-4、β=(0.85, 0.9)）で10ステップ更新する。損失は画面上の cm 単位の MAE。
- 使用中のマウスクリックも較正点として追加する（1秒・0.05以内は無視、60秒で失効）。

## 6. 報告されている精度（画面上の点の誤差 [cm]）【論文 表1】

| 手法 | 年 | MPIIFaceGaze | GazeCapture | EyeDiap | 推論時間 |
|---|---|---|---|---|---|
| iTracker | 2016 | 7.67 | 2.81 | 10.13 | 33ms |
| FullFace | 2017 | 5.65 | – | 7.70 | 175ms |
| Gaze360 | 2019 | 4.66 | – | 6.37 | 24ms |
| AFF-Net | 2021 | 4.21 | **2.30** | 9.25 | 110ms |
| EFE | 2023 | **3.89** | 2.48 | – | 1818ms |
| **BlazeGaze** | 2025 | 4.56 | 2.32 | 7.53 | **0.88ms** |

- 精度は最新の重いモデルと同程度で、速度は桁違いに速い。
- 実際の作業（Eye of the Typer、20分）では、WebGazer の誤差が 7.79→11.62cm（+49%）に増えたのに対し、WebEyeTrack は 7.24→8.72cm（+20%）にとどまった【論文 5.3】。

## 7. このアプリでの再現内容

| 要素 | WebEyeTrack | このアプリ |
|---|---|---|
| 顔のランドマーク | MediaPipe Face Landmarker（.task） | **同じモデルファイル・同じ設定**。BGR の画像をそのまま渡す点も同じ。ただし検出に失敗したときだけ RGB で再試行する |
| 目の画像・頭部ベクトル・顔の3D復元・EAR | Python/numpy/OpenCV | **同じ式で移植**。元のコードと数値が一致することを確認済み（同じ OpenCV なら目の画像は画素単位で完全一致） |
| BlazeGaze エンコーダ | TensorFlow/Keras | **公開重みを ONNX に変換して OpenCV DNN で実行**（`tools/convert_blazegaze.py`）。Keras との差は 1e-6 程度 |
| 視線 MLP と個人適応 | TensorFlow（GradientTape + Adam） | **numpy で同じ式の手書き勾配と Keras 3 の Adam**。TensorFlow との差は予測で約2e-5 |
| 較正の手順・クリック較正・カルマンフィルタ・表示範囲の制限 | demo/ | 同じパラメータで実装 |
| 学習済み重み | MPIIFaceGaze で学習（公開されている唯一の Python 用の重み） | 同じもの |
| **第1・第2段階の学習そのもの** | 公開スクリプトあり | **未実施**。MPIIFaceGaze・GazeCapture のダウンロードと GPU での学習が必要。公開されている学習済み重みを使っている |

- 実行時に TensorFlow は不要で、推論は OpenCV DNN で行う。
- `tests/test_core.py` の `TestWebEyeTrackParity` が、元の TensorFlow 実装で作った参照値（`tests/data/blazegaze_ref.npz`）との一致を検査する。
- 旧方式（虹彩ランドマーク + リッジ回帰）は `--engine classic` で使える。

## 8. このPC・このユーザーでの評価（録画データ `profiles/sessions/20261015_141437`）
- **録画条件:** 画面 30×19cm（1920×1200）、顔までの距離 約55cm（1cm ≈ 64px、1° ≈ 0.96cm）。
- **学習:** 較正用の点（静止24点 + 頭を動かす3点）で学習する。
- **評価:** 較正に使わない点で評価する。同じ姿勢で12点、座る位置や距離を変えた後で8点。
- **値:** 1点を見ている間の推定を平均した誤差（`tools/benchmark.py`）。

| 方式 | 同じ姿勢 | 姿勢を変えた後 |
|---|---|---|
| classic（虹彩 + 頭部姿勢 + 顔位置 → リッジ） | **142px / 2.2cm / 2.3°** | 807px / 12.6cm / 13.0° |
| WebEyeTrack（元の4点手順） | 312px / 4.9cm / 5.1° | 484px / 7.6cm / 7.9° |
| WebEyeTrack（24点で適応） | 269px / 4.2cm / 4.4° | 371px / 5.8cm / 6.0° |
| hybrid-PCA（CNN 埋め込み + 虹彩 + 頭部 + 顔位置） | 168px / 2.6cm / 2.7° | 429px / 6.7cm / 7.0° |
| **stack（WebEyeTrack の予測 + 虹彩 u, v + 開眼度 → 線形リッジ）** | 190px / 3.0cm / 3.1° | **197px / 3.1cm / 3.2°** |

**分かったこと:**
- WebEyeTrack の元の手順の誤差（4.9cm）は、論文の MPIIFaceGaze の値（4.56cm）とほぼ同じだった。移植が正しいことの裏付けにもなる。
- 顔の位置・距離の特徴量は、較正中の姿勢では精度を上げる。一方で、姿勢を変えると外挿が崩れる。classic では 2.2cm が 12.6cm になった。
- CNN（WebEyeTrack）の予測は、姿勢の変化に強いが粗い。虹彩の位置は細かいが、姿勢の変化に弱い。両者を線形に組み合わせると、**姿勢を変えてもほぼ劣化しない約3cm（約3°）**になった。
- 虹彩の位置は、FaceMesh（虹彩専用の精密化モデル付き）から取った方が、FaceLandmarker（BGR 入力）から取るより良かった。姿勢変化後で 197px と 280px。
- **注意:** 評価は1人・1回の録画で、評価点は20点しかない。また、方式を選ぶときに評価点の結果を見ている。別の日にもう一度録画し、`tools/benchmark.py` で再確認するのが望ましい。

この結果から、アプリの既定エンジンを `--engine hybrid`（= stack）にした。
