# Webカメラ リアルタイム視線推定 (OpenCV + MediaPipe)

通常のRGB Webカメラだけで「画面のどこを見ているか」を推定し、軌跡・ヒートマップ表示と、
**視線で選択 / 長い瞬きで決定** するUIデモまでを含みます。

## 視線推定エンジン
- **`--engine hybrid`（既定）**: WebEyeTrack の予測と、FaceMesh の虹彩位置を組み合わせた個人の線形回帰。録画データでの評価で最も頑健だった。同じ姿勢で約3.0cm、座る位置を変えた後で約3.1cm（[docs/research.md](docs/research.md) の8章）。較正は静止24点と頭を動かす3点で、約60秒。
- **`--engine webeyetrack`**: **WebEyeTrack（Davalos ら 2025）と同じ構成**。
  - 処理の流れ: MediaPipe Face Landmarker → 正面化した目の画像（128×512）+ 頭部ベクトル + 実寸の顔3D位置 → BlazeGaze（CNN + MLP）→ アフィン補正 → カルマンフィルタ
  - 個人適応: 4点の較正で MLP を Adam で適応させる。使用中にマウスでクリックすると、その位置でも追加較正する
  - 実装: 公開されている学習済み重み（MIT）を ONNX に変換して **OpenCV DNN** で推論し、適応は numpy で行う。元の TensorFlow 実装と数値が一致することを確認済み
  - 調査の詳細と再現の範囲は [docs/research.md](docs/research.md) を参照
- `--engine classic`: 旧方式（虹彩ランドマーク + 頭部姿勢 + リッジ回帰。静止点16点 + 頭を動かす3点で較正）

## セットアップ・起動 (Ubuntu 20.04 / Python 3.8+)
```bash
./setup.sh                    # venv 作成 + 依存インストール (python3-venv, python3-pip が必要)
.venv/bin/python run_gaze.py  # 全画面で起動 (--windowed でウィンドウ表示)
```
主なオプション: `--camera 0|動画ファイル`, `--width/--height`, `--screen 1920x1080`, `--profile 名前`, `--load`(保存済み較正を使う)

## 使い方
1. 起動後 **SPACE** でキャリブレーション開始。画面を動く点を目だけで追う(約16秒)。
2. 完了画面に交差検証誤差が出る。**SPACE** でトラッキング開始 (較正は `profiles/` に保存)。
3. キー: `1` 軌跡/ヒートマップ画面, `2` キーパッドUI, `H` ヒートマップ, `T` 軌跡, `V` カメラ映像, `R` リセット, `S` スクショ, `C` 再較正, `Q`/Esc 終了。
4. キーパッドUI: 視線を置いたボタンが選択(0.15秒滞在で切替・ヒステリシス付き)。
   **0.55秒以上目を閉じ続ける**と決定(`--long-blink 秒` / 実行中は `,` `.` で±0.05秒。較正中に観測した通常の瞬きから自動調整もする)。
   決定時間の半分を過ぎると進行リングが出る。通常の瞬き(~0.1-0.4秒)は無視される。
   トラッキング画面で長い瞬きをすると、その位置にマーカーが残る。

## 起動と較正の保存
- 保存済みの較正（`profiles/default.*`）があれば、**起動時に自動で読み込み**、較正を飛ばしてメニューから始める。最初からやり直すときは `--recalibrate` を付けるか、`C` キーかメニューの「再較正」を使う。
- メニューの「追加学習」は、**前回までの較正データに今回の分を足して学習し直し**、保存する（`profiles/default.hcal.npz` に蓄積）。

## 目線サッカー 11人制 (メニューの 1)
eFootball の操作体系とルールを参考にしたオリジナル作品（名前・見た目・実在のチームは使わない）。コートは105×68mで両チーム4-3-3。カメラはボールを追い、右下にミニマップを出す。
- **ボタン配置:** **eFootball スマホ版（バーチャルパッド）**のボタン構成をキーボードに写した（Game8 のモバイル版操作一覧で確認）。
  - 左スティック ＝ WASD
  - **ボタンのフリック ＝ そのボタンのキー＋矢印キー**（押している矢印の向きにフリックしたことになる）
  - 配置は `gazekit/soccer11.py` の `KEYS` で変えられる

| ボタン（キー） | タップ | ↑／↓ | ← | → |
|---|---|---|---|---|
| パス（K） | グラウンダーパス（クロスエリアではグラウンダークロス） | フライパス／クロス | インパクトグラウンダー | インパクトフライ |
| スルーパス（I） | スルーパス | フライスルー | インパクトスルー | インパクトフライスルー |
| シュート（J、長押しでパワー） | シュート | ↑ ループ／↓ コントロール | インパクトシュート | インパクトシュート |

| 操作 | 攻撃 | 守備 |
|---|---|---|
| ダッシュ（Shift） | 長押しでダッシュ。**タップしてから WASD を弾くとフェイント** | — |
| 左側（Q）を2回タップ | ドリブル停止（ダッシュ中はボディコンタクト） | ショルダーチャージ |
| K | （パス） | 長押しでマッチアップ。↑ でチームプレス |
| I | （スルーパス） | 長押しでプレス（ボールに寄せる）。自陣で ↓ なら GK 飛び出し |
| カーソル（U） | — | タップでカーソルチェンジ。＋矢印でその方向の選手へ |
| J／L | — | タックル／スライディング（スマホ版の一覧で未確認のため、家庭用版の割り当てに準じる） |
- **カーソルチェンジ:** 「ボールに近く、ボールより自陣ゴール側にいる」選手を選ぶ。抜かれた選手より、後ろで待つ味方が優先される。自動の切り替えは、今の選手より明らかに良い選手がいるときだけ、1秒以上空けて行う。守備中は、**カーソル（U）で切り替わる選手に小さな ▽ と「U」を常に表示**する。
- **ルール:** スローイン、ゴールキック、コーナーキック、オフサイド、ファウル（フリーキック、エリア内は PK）、キックオフ。セットプレーでは、方向キーと J / U / K で蹴る（FK・PK は L 長押しでシュート）
- **視線:** 見つめている味方へのパスコースを CPU が読む。ノールックパスができる。**PK ではキーパーがあなたの見ている側に寄る**
- **対戦への備え:** 各チームを「人」か「CPU」かで切り替えられる設計（`ctrl_kind`）

## 目線フットサル (メニューの 2)
5対5の見下ろし型サッカー（オリジナル作品。eFootball の操作体系を参考にしたが、名前・見た目・実在のチームは使っていない）。
- **操作:** WASD / 矢印で移動、Shift でダッシュ。J でパス（守備時はタックル）、K でスルーパス、L でシュート。I で操作選手の切り替え、P で一時停止、Esc でメニューに戻る。
- **CPU があなたの視線を読む:** 味方を約0.3秒見つめると、CPU の守備がそのパスコースに寄る。画面には赤い点線と「読んでる!」が出る。見ている味方へそのままパスすると、カットされやすい。
- **ノールックパス:** 見ている味方とは別の味方へパスすると、守備が約0.45秒固まる（「?」が出る）。パスもカットされにくい。
- **ノールックシュート:** 相手ゴールの片側を見るとキーパーがそちらに寄るので、逆側へ打つと決まりやすい。
- **シミュレーションでの検証:** 自動操作で3分の試合を回した。受け手を見てからパスし続けると、約65%がカットされて大敗した。ノールックを使うと、カットは約15%で互角になった。

## 視線メニューとゲーム (較正後に自動で表示 / `M` か Esc)
すべて「見て選び、長い瞬きで決定」で操作する。視線誤差(約100px)に合わせ、的は画面の数分の一の大きさ。
- **クイズ**: 4択×8問。画面を4分割した大きなパネルを見て、長い瞬きで回答。計算問題+講義(OpenCV/OpenGL)関連の問題。
- **モグラたたき**: 3×3。モグラを0.45秒見つめると叩く(長い瞬きでも可)。金(+30)は短時間、爆弾(-20)は見つめてはいけない。
  モグラの黒目が視線の方向を見る。45秒、コンボボーナスあり。自己ベストは `profiles/highscore.json`。
- **おえかき / 視線ヒートマップ / 追加学習 / 再較正** もメニューから選べる。各画面左上の「◀ メニュー」を見て長い瞬きで戻る。
- 日本語は Pillow + Noto Sans CJK で描画(OpenCV の putText は日本語非対応のため)。

## 較正と追加学習 (静止点を見つめる方式)
動く点の追従は、視線の遅れ(反応時間+カメラ/処理遅延)で教師データがずれるため、**静止した点を見つめる方式**に変更した。
- **較正 (SPACE / `C`)**: 4x4=16点が順に出る。**ただ見るだけ**(クリック不要)。点が出てから0.6秒は視線が移動中なので捨て、
  その後の0.8秒のフレームを採用(点ごとに外れ値除去)。所要約25秒。
- **追加学習 (`4`)**: ランダムな12点を見るだけ。新旧モデルを検証用の点で比較し、**改善した場合だけ採用**。
- **誤差の表示**: 「見ていない点」への汎化誤差(1点抜き交差検証)を px で表示する。各注視の予測を平均した値
  (実行時の平滑化後に近い)で、画面の角の点を除いた予測(外挿)も含むため、実際の中央付近の精度より厳しめに出る。
- **特徴量の自動選択**: 両目平均の虹彩位置(u,v)・開眼度・頭部の上下向きなど6通りの組を、点単位の交差検証で選ぶ
  (十数点では少ない特徴量ほど過学習しにくい。実データで全10特徴の線形より約15%改善した)。
- **応答遅延の推定**: 点が切り替わってから推定視線が前の点→新しい点の中間に達するまでの時間を、較正中の時系列から
  中央値で計算して完了画面に表示 (人の反応時間 + カメラ/処理遅延の合計。内訳は分離できない)。
- 回帰は点(グループ)ごとに寄与を等しくし、次数とλを点単位の交差検証で選ぶ。
- 旧方式(動く点)は、開始画面で `M` を押すと使える。
- **頭の動きへの対策**: 較正の最後に「点を見たまま頭を左右上下に動かす」点を3つ(各6秒)入れる。視線が固定で頭だけ動くデータが
  入ることで頭部姿勢(solvePnP の向き・顔の位置)の係数が学習でき、頭を動かしてもカーソルが動きにくくなる
  (模擬データで頭を±8°程度回したときのずれ 745px→105px)。先行研究では幾何モデル(頭部姿勢×眼球回転→画面平面と交差)や
  画像の正規化(Sugano 2014, Zhang 2018)で扱うのが主流だが、カメラ較正が必要になるため、回帰+データ収集で対処した。

## 描画モード (`5` キー)
視線でお絵かき・文字書き。**SPACE を押している間だけ**線が引かれる(X11のキー状態を直接読むので離すと確実に止まる)。
長い瞬きでペンの上げ下げ(トグル)もできる(両手が使えない場合)。線は「遅れてついてくる筆」(デッドゾーン22px)で滑らかにし、
目を閉じている間は線を切る。キー: `R G B Y W` 色, `K` 消しゴム, `+/-` 太さ, `U` 取り消し, `X` 全消去, `S` 保存(PNG), `Esc`/`5` 戻る。
視線誤差は約100pxなので、文字は画面いっぱいの大きさで書くこと。

## 実PC操作モード (`3` キー)
視線でOSのマウスカーソルを動かし、長い瞬きでクリックする。
- カーソルはデッドゾーン(35px)付きで追従し、ガタつきを抑える。
- **ズームクリック**: 視線誤差(数十〜100px)では小さなボタンを押せないため、長い瞬き → 周辺を4倍に拡大して再表示 → もう一度視線で狙って長い瞬き、の2段階で実効誤差を約1/4にする。8秒放置でキャンセル。
- 画面左上隅を見て長い瞬き = 一時停止/再開 (意図しない操作の防止)。`Z` ズームON/OFF, `P` 一時停止, `3` 戻る。
- **カーソル操作**: `/dev/uinput` の仮想ポインタ(Wayland/X11共通)を優先し、使えなければ Xorg セッションのみ X11 XTest。
  uinput は一度だけ `./enable_uinput.sh` で権限を付ける。
- **ズーム用の画面取得**: X11 は mss、Wayland は XDG Desktop Portal の Screenshot(jeepney経由, 約0.7秒)。
  ポータルが書く `~/Pictures` のファイルは読み込み後に削除する。取得できない時は格子表示(クリック位置の精度は同じ)。

## 手法 (調査に基づく選定)
最近の研究 (WebEyeTrack 2025 など) も「顔ランドマーク + 頭部姿勢 + 少量の個人キャリブレーション」が
CPUでリアルタイムに動き、保守しやすい主流構成。深層の視線方向モデル(L2CS-Net, ETH-XGaze系)は
汎用で約4°の誤差が出る上、結局画面座標への較正が必要でCPUでは重いため、今回は採用せず、後から特徴量として追加できる構造にした。

| 要素 | 採用 | 理由 |
|---|---|---|
| 顔・虹彩検出 | MediaPipe FaceMesh (refine_landmarks, 478点) | CPUで高速。虹彩中心・まぶたが取れる。モデルはwheel同梱で追加DL不要 |
| 特徴量 | 虹彩の目頭-目尻基準の相対位置(両目, ロール不変)・開眼度・頭部姿勢・顔位置/大きさ | 頭部姿勢は OpenCV `solvePnP` (汎用3D顔モデル, 前フレーム初期値で安定化) |
| 較正 | 滑らかに画面全体を巡る追従点 (横6行+縦3列, 角を丸めた軌跡) | 数百サンプルが短時間で集まる。眼は点より遅れるため遅延(0〜0.3s)を CV で自動推定 |
| 回帰 | 標準化 + リッジ回帰 (線形/2次多項式・λ を時間ブロックCVで自動選択, MAD外れ値除去) | 少データでも過学習しにくく、numpyのみ |
| 平滑化 | 3点メディアン → One Euro Filter | 静止時は安定、素早い移動は低遅延 |
| 瞬き | 開眼度/個人baseline の比 + ヒステリシス + 継続時間による状態機械 | 較正中に baseline 取得、使用中も緩やかに追従 |
| 瞬き中の視線 | 目が十分開いていないフレームは視線更新を凍結 | 閉じかけの虹彩は誤推定になるため。選択ボタンは閉じる直前の状態を保持 |

OpenCV の利用: カメラ取得(V4L2/MJPG), `solvePnP`/`Rodrigues`, 描画全般, ヒートマップのぼかし・カラーマップ, 全画面表示。

## 精度の目安と注意
- 一般にWebカメラ(非赤外)の限界は約2〜3cm(1.5〜3°)程度。ボタンは大きめに設計している。
- 較正後に頭や姿勢を大きく動かすと精度が落ちる。ずれたら `C` で再較正(16秒)。
- 画面内文字はOpenCVの標準フォントのため英語。
- 開発機は Ubuntu 24.04 / Python 3.12 で動作確認。20.04 (Python 3.8) 向けにはコードの構文互換と依存の範囲指定を行ったが、**20.04実機では未検証**。

## 精度の比較 (評価用データの録画)
```bash
.venv/bin/python run_gaze.py --engine classic --record   # SPACE で開始、約2分。点を見つめるだけ
.venv/bin/python tools/benchmark.py profiles/sessions/<日時>
```
較正用の点 (5x4 + WebEyeTrack の4点 + 頭を動かす3点) と、較正に使わない評価用の点 (同じ姿勢12点 / 姿勢を変えた後8点) を録画する。
classic / wet_4pt / wet_allpts / hybrid を同じデータで学習・評価し、誤差を px・cm・視角[deg] で比較する
(フレーム単位と、注視ごとに平均した値)。
